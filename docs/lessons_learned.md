# Lessons learned (read before starting work)

Sandblood build guide: https://claude.ai/artifact/LBNp22258n18mRFtk2ke4i (Skate Park playbook: https://claude.ai/artifact/WtmrkVRtizP8oJBRwhxdWW). Add a row here whenever something goes wrong.

| What happened | Rule |
| --- | --- |
| Subagents messaged the user directly | Never call `mcp__hearthbot__` tools. Report only to the lead. |
| A global `flock` around every Godot run deadlocked agents | Only `godot --import` takes /tmp/<project>_import.lock. Never wrap tools/*.sh in flock. |
| Sub-orchestrator agents had no Agent tool | Nested fan-out needs the Workflow tool, or the lead starts every worker. |
| 4 cloud cores cap Godot runs | Use `tools/check_all.sh` locally and the GitHub Actions matrix (`checks`) for scale. |
| A GPU glitch was blamed on a guess | Sample screenshot pixels and reproduce first. If it can't be reproduced, ship toggles. |
| Wall ends were accepted as floor (`floor_max_angle` 80°), so a fake vert launch cut speed to 15% | Measure snags with `tools/snag_sweep.sh`, then fix the traced mechanism. |
| A lab WARN almost undid a design choice (strong halfpipe pump) | Check a WARN against the player's stated wishes before tuning it away. |
| `git commit -a` pushed another worker's half-finished file | The lead stages files by name while workers are editing. |
| A z-fighting floor pad | Lift the mesh, never the collider (`PieceKit.floor_pad`). |
| A `-s` render script couldn't see autoloads | `load()` game classes inside a deferred call. |
| A fix looked plausible but the bug predated the changed code | Check git history for when a bug first appeared. |
| Feel bugs were found by the player, not by us | Build the debug layer and the bot before content: tunables, debug frame, snapshot/replay, recorder, overlay, lab, bot. |
| Ramps had knife-edge side walls under 0.3 m | Piece rule: no collision edge under the skater's radius, side walls run below ground, no coplanar floors. |
| Shader compile failed: `MODELVIEW_MATRIX` used in a fragment shader; a disc rendered culled | `MODELVIEW_MATRIX` is vertex-only (use `VIEW_MATRIX * MODEL_MATRIX` in fragment); Godot front faces wind clockwise |
| The brief said finishers start at `blood / 5.0 < 0.4`, but death is at 2.5 L, so it could never fire | Normalise between the death line and full (`health.blood_frac()`); check a new threshold against the existing ones |
| Thin poles and an awning cast hard streaks across the sand | Only fighters, walls and big shapes cast shadows; thin decorative meshes don't |
| A worker typed a parameter as `Fighter` before that class was committed; CI lint failed on the pushed tree | Code against an uncommitted contract class with duck typing (`Node3D`), and lint a clean clone before pushing when workers are mid-flight |
| Mid-fight restore of a melee diverges (0.2 m after 1 s) though idle restore and fresh starts are exact | Record matches as seed + inputs from tick 0 and replay from the start; treat mid-fight restore as approximate |
| Same-seed bot matches split late in about 40% of fresh runs; a second match in one process always diverged | Jolt's contact order is thread-dependent: sort contacts before first-per-key debounce. Run every same-seed repeat in a fresh process |
| A knocked-off armor prop had a layer the fighters scan but a mask that ignored them; Godot made it an immovable block that pinned a fallen fighter's thigh for 40 s (seed 5007) | Give dynamic props symmetric masks, or no layer at all; never one-sided |
| Owner saw "green blood": shadows on orange sand read olive/teal because the only fill light was a blue sky ambient, and damp sand darkened the warm part | Use a warm colour ambient in a sand arena and sample shadow pixel colours (hue) in renders before blaming the blood shaders |
| Round 4 started from round 3's numbers (126 hits/min), but the arena-footwork brain change had already moved them to 95 | Re-measure the baseline on the current tree before tuning; numbers go stale after any brain or physics change |
| Closing the ENet peer from inside its own `poll()` (a disconnect signal handler) crashed with signal 11 | Never close a MultiplayerPeer from its own signal; defer the close to the next idle frame |
| ENet's packet throttle silently dropped about half the unreliable snapshots after a frame hitch | Switch the ENet throttle off on connect (deceleration 0) for snapshot streams |
| A shader-hidden crowd twin (`VERTEX *= 0`) still cost its vertices, and Godot's primitive counter ignores MultiMesh instances, so the crowd looked cheap | Cut instances with `visible_instance_count`; count MultiMesh triangles yourself and time script cost separately |
| EOSG's create-user login path fires no Connect login callback, so the runtime never learned the local user | Log in a second time after creating the device user; mock a plugin's native singleton to run its real GDScript without the binaries |
| A reliable events packet could exceed the EOS relay's 1164-byte limit and be silently dropped | Split network packets by bytes, not by record count (`NetEvents.encode_chunks`) |
| A bot run hung for 15 min and wrote a 334 MB log: another worker's half-saved `fighter_brain.gd` failed to parse at launch, so every tick errored | Watch a long bot run's log size or error lines, not just its exit; re-run balance after a shared script stops changing |
| Spear AI aimed open-loop and thrust from walking speed, so its "thrusts" were sub-3 m/s shaft touches (0 wins of 10) | For long weapons, steer on the measured blade line and check speed against damage_min_speed; reach comes from footwork, not arm extension |
| Two fighters with the same weapon shared one cached glb `Mesh`; per-instance override materials on a shared mesh gave `Parameter "material" is null` at teardown | Duplicate an instanced glb's mesh before setting surface override materials |
| Fist fights could never be won: no bleeding, and the time-out judge only compared blood | Every win rule needs a fallback for its zero case (level blood falls back to body hp) |
| Container restarts killed running workers three times | Workers leave WIP in the tree; relaunch a worker on that WIP with the prior findings, never from scratch |
| Houdini 22's glTF ROP exports every material as `alphaMode BLEND` | Force imported art opaque (or set it in the ROP); `hipFile.save` needs its folder made first; run Houdini builds with `--only=<ids>` |
| 2026-10-22 | Fighters looked tiptoe and floating: the pelvis force carried and pushed the body while the legs were posed from a sine phase, so the PD-lagged legs trailed a stride behind with toes on the sand (planted foot pitch 48°, contact slip 1.9 m/s walking) | Plan feet in world space (GaitLogic: planted feet hold, land where the foot really is), move feet with a PD force whose reaction goes on the pelvis, and measure gait with out/loco_probe.gd before tuning |
| Tucking legs on a timer while standing made the roll hop, and turning about the pelvis vaulted it into a handstand | Dip on planted feet first, tuck only once low, and let the support hold only part of the weight while tucked |
| The lead pushed a red tree: `(lint; tests; sims) && git commit` only checks the last command of the subshell | Gate commits on the summary lines (`failed=0`, `problems=0`), not on a subshell exit code |
| A worker cleared its own hung Godot with `pkill godot` and killed another worker's render | Kill only your own PIDs (`kill <pid>`); never `pkill godot` while other workers run |
| A pool re-stamped the sand 30x a second at an unchanged radius (25 ms at high in the worst gore case), and a per-texel loop called three sines | Time sections in a scripted worst case (`perf.sh --heavy`) before guessing; gate repeated work on a changed input, hoist per-texel trig into a table |
| A rate-per-second sim check failed when a bot fight ended in 4 s: the opening clash and finisher burst made the mean 36/s | Divide rates by a floor duration (8 s) so short fights do not inflate them; bursts belong to the max/s check |
| perf.sh averaged Performance.TIME_PROCESS per frame and reported 36 ms on low; that monitor updates about once a second with the slowest frame, and the first run included shader compiles (real: 5.2 ms) | Time real frames (ticks between frames, p50/p95/max) after a warm-up; never average a once-per-second monitor |
| Remote Control on the user's PC refused a git push approved through the lead | Actions on the user's PC that its permission check guards need the user's own words in that session; ask them to type it there |
| Net sims and tests opened fixed ports (17931, 17941, 17961, 17981, discovery 17790..97, the stub's 7777), so two suites on one machine failed with "Could not listen on port 17961", and two Quick Match runs could even find each other's peers by UDP | Sims take ports from `net_port(slot)` in `tests/sim/sim_base.gd` (a 64-port block per OS process id, plus a slot); the stub reads `--net-port`; the game's default port is unchanged. Never write a literal port in a test |
| check_all.sh logged to a shared /tmp/check, so two runs overwrote each other's logs, and it ended on a table with no single verdict | Each run logs to its own mktemp dir; the last line is `CHECK_ALL PASS` or `CHECK_ALL FAIL`, and the exit code matches |
| Agent calls with isolation "remote" ran as local background subagents on the same 4-core box (load 70, branches barely landed) and some checked out branches in the shared main tree | Verify where an agent runs (cwd, list_sessions) before claiming extra machines; real scale-out is separate cloud sessions or the Actions matrix; keep local workers to the core count's budget |
| A "concurrency flake" (Identifier "FighterWarmup" not declared, sims after it fail) was really another worker editing the same working tree while a suite ran; a second worker also committed with `git add -A` into the shared tree | Run a long suite in your own clone, not a tree others edit; stage named files, never `git add -A` in a shared checkout |
| A modded client's input tick near 2^32 made the host's jitter buffer walk every tick of the gap (~340 s freeze per packet), and a lone "dropped" report credited its sender with a win, so blocking the game's traffic while losing scored a forfeit | Parse every peer packet as hostile: bound counts, sizes and jumps, loop over what is held (never over a range the sender picked), read decoded fields with type checks, and fuzz each parser with a Logger counting errors (`test_net_fuzz`); a rating rule that runs on the reporter's own device must not reward a silence the reporter can cause |
| A skipped instant replay left a severed head 3.4 m off: bodies placed with `global_transform` from an input event were synced back to the physics server's older pose by the next step, before the transform flush reached the server | Place a body that must stay put with both `global_transform` and `PhysicsServer3D.body_set_state(TRANSFORM)`, and unfreeze it before placing it |
| The instant replay paused the online driver, and 5 s without packets (`DISCONNECT_TICKS`) ended the session | Anything that pauses a net driver keeps the session alive (KillCam sends a one-byte packet a few times a second) |
| The finisher slow motion's first frame ran the camera and effects five times too far: the frame's delta was scaled by the old time scale, but `real_delta` divided by the new one that physics had just set | Divide a frame's delta by the time scale in force when the frame began (`RealClock`); a scale change inside physics applies from the next frame |
| An online loss read "MORS / Gannicus wins": online matches take their fighter names from the seed, not from the lobby, and a unit test leaked a never-freed `OnlineService` node | Name the opponent from the service or session on online panels; free every Node a unit test makes (a leak warning ends the whole test run) |
| perf.sh averaged `Performance.TIME_PROCESS` / `TIME_PHYSICS_PROCESS` per frame and blamed 24 ms on GDScript; those monitors hold the slowest frame of the last second (and include the renderer), so spikes were counted every frame | Time real frames yourself (ticks between frames, p50/p95/max) and sections with `Time.get_ticks_usec` marks; skip warm-up frames before measuring |
| A beheading stalled its frame ~10 ms per cut building gore caps (glb instance + procedural face) in the frame of the blow | Build per-event visuals ahead (spread one per frame) and only attach them when the event comes; warm first-use shaders off-screen once per session |
| On a phone the first finger is also Godot's emulated left mouse button, so "auto" input read it as SWING: walking with the left thumb swung the sword (sim_touch, 210 of 210 ticks) | Ignore mouse events with `device == InputEvent.DEVICE_ID_EMULATION` wherever mouse buttons are read; prove touch with synthetic `InputEventScreenTouch` through `Input.parse_input_event` |
| Workers share one scratchpad; a worker `rm -rf`'d a `before/` folder there that held another worker's captures | Keep scratch files under `scratchpad/<branch>/`; never delete a scratch path you did not create in this run |
| A client-side hand lead was taken back as soon as the ack passed the press, before the shown arm moved (snapshot bodies lag their ack by a physics step), so swings stepped back 15-17 cm | Hand a prediction over no faster than the shown pose advances, and find the ack-to-pose lag by measuring before tuning the model |
| A grab held by a PD spring between two 1.7 kg forearms slipped in 0.15 s: gains stiff enough to hold an arm went unstable at 60 Hz (damping c·dt/m over 2), and the holding fist bounced off the held wrist and hilt | Tie two bodies with a joint (limits for slack) and collision exceptions for what the hand wraps round; check an explicit spring's damping against the lighter body's mass |
| The CPU's stacked close-move chances tested `r < chance` per branch, so a grab (0.2%) inside a shove's range (0.6%) could never fire | One draw, cumulative thresholds per option; a unit test per option at a distance where it is reachable |
| sim_practice failed only after sim_close_combat (thrust step stuck, tip under 1 m/s): no game data leaked (fighter state, Tuning, CombatData, rig, physics params identical at start), but the shared physics space changed the run from tick 8, and plain RigidBody3D churn with no game code changed it too (781 ticks to 1569); after close combat the swing step left the player 0.8 m from the dummy with the gladius lying on its torso, so every thrust was jammed | A Jolt space's results depend on every body it created and freed before. A long or chaotic sim builds in `sandbox(true)` (its own World3D, a fresh space); `sim_sandbox_isolation` checks that such a run replays bit for bit after churn |
| A render capture keyed on frame counts looked hung for 5 min at load 45: wall-clock frames crawled and the intro timer ran on real time | Run captures with `--fixed-fps 60` so frames, timers and physics advance together, and print a line per saved shot |
| A sim that died on a script error (net_menu, while other workers ran net sims on the same ports) printed no rows and the suite still said failed=0 | Read the SIM lines, not just the totals: a sim that returns no rows is a failure |
| A new sim listed before sim_audio_bot moved its footstep rate from 5.2 to 7.3 steps/s (limit 7.0) with no change to fighters or audio: the bot fights depend on what ran earlier in the process | Append new sims at the end of SIM_FILES, and give order-sensitive sims their own process |
| Merging the results screen onto the killcam branch: sim_match_show waited 600 ticks for the results, the instant replay made it 688, and the sim died on a null and printed no rows; sim_net_cheat still read the soak sim's removed `PORT` | Size a sim's wait from every step between its trigger and the state it waits for (delays, replays) and guard what the wait returns; lint the merged tree, not each side |
| The Android emulator job passed while 186 lit scene shaders failed to link ("Fragment shader active uniforms exceed GL_MAX_FRAGMENT_UNIFORM_VECTORS (261)") under `-gpu swiftshader_indirect`; the gate only grepped for SCRIPT ERROR | Emulator uses `-gpu swangle_indirect` (ANGLE: 0 failures); tools/android_ci_run.sh fails on `Program linking failed` too. A green smoke test must also prove it rendered: look at the fight frame |
| `yes \| sdkmanager ...` failed the Actions step with exit 141 (bash runs with pipefail; `yes` dies of SIGPIPE) | `set +o pipefail` around it and check the installed file instead of the pipeline status |
| Actions artifact downloads (blob.core.windows.net) are blocked from the cloud box, so screenshots uploaded as artifacts could not be seen | The job prints a 256 px JPEG of the game's own frame as base64 in the log (FIGHT_JPG_BEGIN/END) |
| HitFx sets a struck part's `material_overlay` for its flash and then clears it to null, so any other overlay on fighter meshes is wiped on the next hit | Draw extra per-mesh layers (wound marks, weapon blood) as shell MeshInstance3Ds outside Look/ArmorSlot that follow their source's visibility; never share `material_overlay` |
| The textured Houdini glbs each embedded their own copies of the library maps (203 images, 27 distinct); imported as is, Godot extracted 203 JPEGs, lossless and uncompressed in VRAM (~1.4 MB each), so every model on screen paid for its own steel and wood maps | Check what a glb embeds before loading it (`images` in its JSON). Point glb materials at shared library textures through the import's external materials (`tools/textured_import.py`) and set library PNGs to VRAM compressed with mipmaps |
| A task said main "soon has" close combat; it was only on two lead integration branches that had split (one had close combat, the other the touch crouch the task also needed), so a branch from main had neither | Before branching, find where the code a task builds on lives (`git ls-remote`, check each candidate for the file); merge the lines you need first and tell the lead how you resolved their conflicts |
| A new sim measuring a hold failed because the hold broke at once in its sandbox (a passive foe's fist "hit" the reaching arm at the reach's own 5 m/s and staggered it), while the same setup held 2.8 s in the sim before it | Measure a new quantity inside a scenario already proven stable, not a fresh copy of it; physics in a new sandbox is not the same run |
| A `git add -A` after a headless Godot run committed 130 generated `.import` files and extracted glb textures; the lead had to drop them in a merge | Stage paths explicitly after any Godot run (`git add data/ tools/ ...`), never `-A` in a tree Godot has imported |
| A full 17-weapon matrix took an hour on the 4-core box, and Actions logs and artifacts can't be downloaded from the cloud session (blob host blocked) | Fan bot fights out over GitHub runners (balance.yml: 20 runners, 5 min) and have a final job commit the merged results back to the branch |
| Adding a weapon (scutum) mid-round shifted every pair's seed index, so before/after runs were no longer paired | Seed from the weapons' own indices (i * 64 + j), stable while weapons are only appended; measure "before" on the same seeds |
| A heavier, blade-heavy dai-katana was expected to swing slower and lose; it won more (69% vs 64%) | Measure every handling change (mass, balance) on its own; revert what doesn't move the number the way you meant |
| Adding the arena dressing's colliders as a separate StaticBody3D flipped sim_net_feel's guard check (client step back 24.7 cm vs host 17.6) even with the body moved 100 m under the floor: one more body reorders Jolt's space | Add static shapes to the existing static body (the wall) rather than a new body; to tell contact from reordering, re-run with the new shapes moved far away |
| A thread placed the whole arena dressing while a local worker was doing the same on lead/integrate-10 | Before starting, check the lead's integrate branches (`git ls-remote origin 'lead/*'`) for the files you will touch, not only main and ramp/* |
| Low-tier blood drops were darker than the medium/high impostors (mean red 132 vs 146): the teardrop mesh was wound counter-clockwise, so `cull_back` dropped the near half and drew the far half, whose normals face away (Godot flips back-face normals too, so `cull_front` looked the same). Before the impostors every tier used that mesh, so tier-vs-tier shots matched and hid it | Debug a shading difference by writing `NORMAL * 0.5 + 0.5` to EMISSION and sampling the centre pixel (blue = facing the camera); check procedural mesh winding against Godot's own SphereMesh in a unit test |
| Sims still passed or failed by suite order after `sandbox(true)` existed (sim_audio_bot's footstep rate, sim_net_cheat): only the sims that opted in were isolated, and a sim that hit a script error returned `[]` with failed=0 | sim_suite now gives every file after the first a fresh root `World3D` and resets statics, Engine, Flags, input, audio and stray nodes (`tests/sim/sim_globals.gd`; a "<file> isolation" row fails if anything still differs); empty results and script errors (a `Logger`) fail; `tools/sim_isolation.sh` compares each file alone with the suite (19 of 20 match; 6 before) |
| Pad focus on the loadout and online screens skipped rows or dead-ended: Godot's neighbour search sees controls scrolled out of a ScrollContainer, so "down" from a row jumped to a footer button drawn over them | Route focus by hand on scrolling screens (`MenuNav.link_screen`) and prove it with `sim_menu_nav` (every control reachable, at landscape and portrait sizes) |
| Menu captures under software GL took 15+ min per launch with several workers rendering | Capture only the shots you need per launch, run before/after from separate worktrees in the background, and keep going on code meanwhile |
| Hand-drawn menu buttons cleared `Button.text`, so `sim_net_quick_flow` (which reads panel buttons by their text) saw empty buttons | Custom-drawn buttons keep their plain label in `text` and hide it with transparent font colours; tests and logs read it |
| The flight recorder took everything from the Match once, at tick 0, so `fight_start_tick` (set later by the offline intro skip, between two physics ticks) never reached the file: a replay ran the time limit from tick 0 and ended 78 ticks early (sim_replay_clock). MatchStats durations also counted the held intro ticks | A value the Match can change after tick 0 is read on every tick and at match_over, not with the header; anything counted "per fight" takes the fight clock (`Match.fight_clock_running()`), never the match tick |
